# Анализ диаграммы системы

На основе анализа диаграммы системы и ее описания, необходимо настроить кеширование в следующих частях:

- Shop API - каталог изделий и готовых заказов
- CRM - метаданные заказов
- MES - дашборд со списком заказов по статусам
- MES - расчет стоимости

# Мотивация

- внедрение кеширования избавит систему от лишних расчетов и запросов
- повышение скорости отклика MES сервиса
- уменьшить нагрузку на БД
- улучшить пользовательский опыт

# Предлагаемое решение

| паттерн кеширования | область применения                           | описание                                                                                        |
|---------------------|----------------------------------------------|-------------------------------------------------------------------------------------------------|
| Cache-Aside         | каталог изделий и готовых заказов            | лучше всего подходит для приложений с большим объёмом запросов на чтение                        |
| Write-Through       | MES API - обновление статусов                | обновляют базу данных синхронно                                                                 |
| Write-Behind        | MES API - принимать заказы в очередь расчета | обновляют базу данных асинхронно                                                                |
| Refresh-Ahead       | MES API - результаты расчет стоимости        | принудительное обновление часто используемых кешированных данных до истечения срока их действия |

## Стратегия инвалидации кеша

Инвалидация по врмени (TTL) - обеспечивает "защиту от забывчивости" для нечасто меняющихся данных

- 5 мин. - список заказов
- 5 мин. - каталог товаров

Инвалидация по ключу - для актуальности критически важных данных

- изменении данных заказа

Инвалидация по событиям - для актуальности критически важных данных

- обновление статуса заказов
- обновление метаданных товара
- изменение цен
